name: add-entity-type
description: Применять, когда нужно добавить новый тип обезличиваемых данных (новую сущность) в triema-masker. Описывает полную процедуру от EntityType до отчёта, чтобы не выводить её заново каждый раз.
---

Сначала ответь на вопрос: это тип для всех или для одного запроса?

Если для одного («замажь даты отгрузки в этом договоре») — кода не трогай.
Пользовательский тип приходит в теле REST-запроса секцией `custom_types`,
компилируется LLM в `CustomTypeSpec` и исполняется одним из executor'ов
(`literals`, `regex`, `regex_context`, `gliner_label`, `gliner_structure`,
`regex_llm_filter`). Файловой конфигурации в проекте нет намеренно — см.
`docs/plans/T1.13-design-notes.md`, решение 2.1.

Шесть шагов ниже — только для **встроенных** типов, которые становятся частью
продукта: у них обязана быть контрольная сумма или регулярка в коде проекта,
разметка в корпусе, порог в воротах и, возможно, место в `CRITICAL_TYPES`.

Добавление встроенного типа затрагивает шесть мест. Пропуск любого даёт тихий
дефект: тип вроде бы поддержан, но не попадает в отчёт или в проверку утечек.

Порядок:

1. `src/masker/model.py` — новый член `EntityType`. Если пропуск этого типа
   означает утечку персональных или платёжных данных, добавить его в
   `CRITICAL_TYPES`: тогда ворота потребуют recall = 1.0. Сразу же —
   `EntityTypeSpec` в `builtin_specs()` (`src/masker/entity_types.py`): там
   `title` для отчёта и UI и `marker_label` для маркера. Без спека
   `test_builtin_registry_matches_enum` покраснеет — это и есть страховка
   от типа, молча выпавшего из отчёта. Шаг 6 закрывается здесь же.
2. `src/masker/detect/rules.py` — регулярка. Если у реквизита есть контрольная
   сумма, функция проверки идёт в `checksums.py` отдельно и покрывается
   тестом с валидным и заведомо битым значением. Регулярка без контрольной
   суммы допустима только там, где её объективно нет (КПП, адрес).
3. `src/masker/mask/plan.py` — правило нормализации (что считать одной и той же
   сущностью) и шаблон маркера.
4. `fixtures/labeled/` — не менее двух документов с этим типом и разметка
   в JSON рядом. Один случай обязан быть «трудным»: перенос строки внутри
   значения, нестандартный разделитель или соседство с похожим числом.
5. `tests/` — тест на детекцию, тест на согласованность маркера, тест на
   отсутствие значения в выходном файле.
6. `src/masker/report/` — проверить, что человекочитаемое имя берётся из
   `EntityTypeSpec.title` (шаг 1), а не из ещё одного словаря рядом.

Затем `make gate`. Смотреть не только на зелёный код возврата, но и на таблицу
метрик: новый тип не должен уронить precision у соседних. Частая причина
такого падения — слишком широкая регулярка, перехватывающая чужие значения.
