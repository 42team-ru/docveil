# AGENTS.md — правила работы над triema-masker

Общий файл для dsh, Claude Code и Codex. `CLAUDE.md` — симлинк на него.

## Что это за проект

Локальный мультиагентный обезличиватель тендерных документов (PDF/DOCX/XLSX)
для АО «Триема». Вход: файл + список типов данных. Выход: файл в исходном
формате, где найденные сущности заменены на маркеры и **подсвечены**, плюс
отчёт о заменах.

Полная постановка — `docs/BRIEF.md`. Архитектура и контракты — `ARCHITECTURE.md`.
Задачи с критериями приёмки — `TASKS.md`.

## Движок

Пайплайн целиком собран на **LangGraph**. Логика живёт в узлах графа,
состояние течёт через `State`, ветвления задаются рёбрами, чекпойнтер SQLite
хранит состояние между шагами. Проектировать и писать код надо в этих
терминах, а не в терминах последовательных вызовов функций.

```
 extract ─► detect ─► profile ─► judge ─┬─(есть вопросы)─► ask_human ─┐
 (парсер)   (3 слоя)  (субъекты)        │                             │
                                        └────────(нет)────────────────┤
                                                                      ▼
                                                                    plan
                                                                      │
                                       ┌──────────────────────────────┤
                                       ▼              ▼               ▼
                              masked_black.*  masked_highlight.*   report
```

`interrupt()` на узле `ask_human` даёт паузу, переживающую перезапуск
процесса: интерфейс спрашивает человека и возвращается к прогону хоть через
час. Рабочий образец графа — `spikes/langgraph_pipeline_spike.py`.

Детекция трёхслойная: правила с контрольными суммами → локальный NER
(Natasha) → LLM-арбитр только на спорном. Обоснование — в `ARCHITECTURE.md`.

## Команды

```bash
make gate      # ЕДИНСТВЕННЫЕ ворота: линт + типы + тесты + предметные метрики
make test      # только pytest
make eval      # метрики precision/recall по размеченному корпусу
make demo      # прогон на fixtures/labeled/*, результат в out/
```

Питон только из `.venv`: `.venv/bin/python`. Пакеты ставить через
`uv pip install --python .venv/bin/python <pkg>` и сразу дописывать в
`pyproject.toml`.

## Агенты

Три роли, одинаковые в Claude Code (`.claude/agents/`) и в Codex (`.codex/`):
оркестратор проектирует и пишет план с критериями приёмки, кодер пишет код и
тесты по плану, дешёвый исполнитель гоняет команды и возвращает факты.

Codex запускать только через `./scripts/codex.sh`, dsh — через
`./scripts/dsh.sh`: обёртки переключают `CODEX_HOME` и `DSH_HOME` на каталоги
в репозитории. Прямой вызов `codex` или `pnpm dsh` возьмёт глобальный конфиг,
и ролей там не будет.

Из dsh доступны подагенты `subagent_codex` и `subagent_claude_code` — при
условии, что в сессии выбран пресет **Триема**. В стандартном пресете эти
строки выключены.

Три ресурса разной природы: Claude Code и Codex — подписки с фиксированной
платой, шлюз — потокенная оплата, GigaChat — продуктовый и в дев-петлю
не тащится. Тарифы и выбор модели под задачу — `docs/ECONOMICS.md`.
Коротко: полная сессия на Opus стоит около 19 центов, поэтому экономить
на выборе модели бессмысленно; экономия имеет смысл только там, где
вызовов сотни — прогон корпуса, разбор пачки документов.

## Определение готовности

Задача не сделана, пока не выполнено всё:

1. `make gate` завершается кодом 0. Вывод приложить целиком, не пересказывать.
2. На каждую новую ветку логики есть тест, который падает без неё.
3. Новые сущности/правила добавлены и в `fixtures/labeled/`, и в отчёт.
4. Ничего не сломано в метриках: recall по критичным типам остался 1.0.

Докладывать «готово» без прошедших ворот запрещено. Если ворота падают —
показать вывод и сказать, что не сходится, а не подгонять тест под код.

## Предметные инварианты (нарушение = провал, а не «мелочь»)

- **Утечки нет.** В выходном файле не должно остаться ни одной исходной строки
  замаскированной сущности — ни в тексте, ни в XML docx/xlsx, ни в текстовом
  слое PDF, ни в метаданных документа (author, /Info, custom properties).
  Проверяется побайтово, а не глазами.
- **Recall важнее precision** для ИНН, паспорта, счетов, ОГРН, СНИЛС.
  Пропущенный ИНН — это утечка. Лишняя маска — косметика.
- **Идемпотентность.** Повторный прогон уже обезличенного документа не должен
  ничего менять.
- **Согласованность псевдонимов.** Одна и та же сущность во всём документе
  получает один и тот же маркер. Маркер строится от профиля и роли:
  `[ПОСТАВЩИК-ИНН]`, `[ПОКУПАТЕЛЬ-ДИРЕКТОР]` — обезличенный договор обязан
  остаться читаемым, иначе им нельзя пользоваться.
- **Судья не спрашивает про критичное.** Сущность из `CRITICAL_TYPES`
  маскируется молча при любой уверенности и в `questions` не попадает.
  Вопросы задаются одной пачкой в одном прерывании графа, а не по одному.
- **Оба документа обезличены по-настоящему.** И чёрный, и подсвеченный
  вариант не содержат исходного текста. Чёрный прямоугольник поверх живого
  текста — самый дорогой дефект в этой предметной области.
- **Структура цела.** Таблицы, ячейки, формулы, нумерация, стили остаются
  на месте. Число абзацев/строк/листов до и после совпадает.
- **Детерминизм.** Никакого `random` без сида от идентификатора документа.
  Два прогона на одном файле дают побайтово одинаковый отчёт.

## Чего не делать

- Вызов модели идёт через `LLMProvider` из `src/masker/llm/`. Это прямое
  требование заказчика №6: замена GigaChat на локальную модель не должна
  трогать логику узлов.
- Сеть в тестах разрешена: E2E-прогон через настоящий GigaChat — часть приёмки.
  Такие тесты помечать `@pytest.mark.e2e`, чтобы их можно было отобрать отдельно
  (`pytest -m e2e`) и чтобы падение сети было видно как падение именно E2E,
  а не как загадочная ошибка юнит-теста.
- Не вызывать LLM там, где хватает регулярки с контрольной суммой. LLM — на роли
  сторон и на спорное, а не на поиск ИНН.
- Не редактировать напрямую `docx`/`xlsx` через строковые замены в XML.
  Только через python-docx / openpyxl, иначе ломается формат.
- Не закрашивать PDF прямоугольником поверх текста: текст остаётся под ним и
  вынимается через copy-paste. Только `apply_redactions()`.
- Не менять сигнатуры в `src/masker/model.py` без правки всех потребителей.

## Стиль

- Русский в докстрингах и сообщениях пользователю, английский в именах кода.
- Типы обязательны на публичных функциях.
- Никаких `except Exception: pass`.

## Ветки и коммиты

- Каждую новую фичу делать в отдельной ветке от актуальной базовой ветки.
- **До первого изменения файлов проверить текущую ветку.** Если это `master`
  или `main`, сначала выполнить `git switch -c <type>/<краткое-имя-задачи>`.
  Допустимы, например, `feat/detect-agent`, `fix/test-gate` и
  `chore/test-layout`.
- **Никогда не коммитить и не пушить прямо в `master`/`main`**, если пользователь
  не дал явное указание именно на прямой коммит и push в эту ветку. Обычный
  запрос «сделай коммит» или «запушь» означает коммит и push *рабочей ветки*,
  а не базовой.
- Перед `git commit` и перед `git push` обязательно вывести
  `git status --short --branch` и убедиться, что активна рабочая ветка и в
  индекс добавлены только файлы текущей задачи.
- Если коммит по ошибке уже сделан в `master`/`main`, остановиться: не пушить
  и не переписывать историю самостоятельно. Сообщить SHA и запросить решение
  о переносе коммита в ветку, revert или другом способе исправления.
- Сообщение коммита должно кратко и однозначно описывать сделанное.
- Не добавлять в коммиты trailer `Co-authored-by` для Codex, Claude или других
  ИИ-ассистентов.
