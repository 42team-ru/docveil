# DocVeil

**Локальный мультиагентный обезличиватель тендерных документов**

Загружаете договор и список типов данных — получаете тот же документ в
исходном формате, где ИНН, ФИО, счета и прочие персональные данные заменены
на читаемые маркеры вроде `[ПОСТАВЩИК-ИНН]`, плюс отчёт о каждой замене и
сертификат, подтверждающий, что исходный текст физически удалён, а не
закрашен.

Постановка задачи заказчика — [`docs/BRIEF.md`](docs/BRIEF.md).

## Результат в цифрах

Не рассказ, а вывод `make gate` / `make bench` на этой кодовой базе,
09.09.2026. Полный вывод ворот прикладывается при сдаче, а не пересказывается.

| Метрика | Значение | Как измерено |
|---|---|---|
| Recall критичных типов (ИНН, ОГРН, СНИЛС, паспорт, счёт) | **1.000** (40/40) | основной корпус, `make eval` |
| Recall критичных типов на holdout | **1.000** (17/17) | документы, на которых детектор не настраивался |
| Утечек в выходных файлах (`leaked_total`) | **0** | побайтовый поиск по тексту, XML, метаданным |
| Устойчивость к искажённому написанию (`robust_recall`) | **0.860** | метаморфный корпус: 357 вариантов одних и тех же сущностей — гомоглифы, разрядка, опечатки, переносы |
| Ложные срабатывания на документе без PII | **2** | негативный корпус (ГОСТ/регламент) |
| Точность кластеризации сущностей в профили (`cluster_purity`) | **1.000** | размеченный корпус |
| Точность определения роли стороны (`role_accuracy`) | **0.833** | профили, где роль явно названа в документе |
| Пересечений подсветки друг с другом (`highlight_overlaps`) | **662** | рендер PDF/DOCX корпуса |
| Отказов сертификата обезличивания / рендера | **0 / 0** | `certificate_failures`, `render_failures` |
| Тестов в `make gate` | **1944**, все зелёные | pytest |
| Время на договор целиком | **0.26 с** | сумма медиан стадий графа, `contract_01.docx`, 5 прогонов |
| Время на скан-PDF, 46 страниц | **24 с** | `make bench` |
| Пиковая память | **545 МиБ** | `make bench`, `resource.getrusage` |
| Карточка договора | 17 полей на 46-страничном PDF | `summary/`, вместо чтения всего документа |

> **Чего здесь сознательно нет.** Прогноз экономии часов ручной вычитки не
> считается: он требует внешнего замера времени человека на том же
> документе, такого замера нет. Подставлять правдоподобное число вместо
> измеренного этот проект прямо запрещает себе (см. «Принципы» ниже). Как
> только замер появится, прогноз встанет в `make bench` отдельной, явно
> помеченной строкой.

## Быстрый старт

```bash
make install     # venv на python 3.14 + зависимости (в backend/)
make gate        # ворота: линт, типы, тесты, предметные метрики
```

Обезличить один файл:

```bash
cd backend
.venv/bin/masker contract.docx --out out/check --types all --redact-style both
```

Что доустановить (tesseract, uv) и что делать при сбое установки —
[`docs/SETUP.md`](docs/SETUP.md). Карта всех настроек, YAML-профиля LLM и
секретов — [`docs/CONFIGURATION.md`](docs/CONFIGURATION.md). Полный разбор
флагов CLI и формата отчёта — [`docs/CLI.md`](docs/CLI.md).

## Пример: что происходит с текстом

Фрагмент реального прогона на тестовом договоре
(`fixtures/labeled/contract_01.docx`, `--profile --redact-style both`),
без единой правки руками:

**До:**

```
Акционерное общество «Триема», ИНН 3662103003, КПП 366201001,
ОГРН 1023601546902, именуемое в дальнейшем «Поставщик», в лице
генерального директора Иванова Ивана Ивановича, с одной стороны, и
Общество с ограниченной ответственностью «Вектор», ИНН 7707083893,
КПП 770701001, именуемое в дальнейшем «Покупатель», в лице директора
Сидоровой Анны Петровны, с другой стороны, заключили договор
о нижеследующем.
```

**После (`masked_highlight.docx`, подсветка жёлтым):**

```
[ПОСТАВЩИК-ОРГАНИЗАЦИЯ], ИНН [ПОСТАВЩИК-ИНН], КПП [ПОСТАВЩИК-КПП],
ОГРН [ПОСТАВЩИК-ОГРН], именуемое в дальнейшем «Поставщик», в лице
генерального директора [ПОСТАВЩИК-ФИО-1], с одной стороны, и
[ПОКУПАТЕЛЬ-ОРГАНИЗАЦИЯ], ИНН [ПОКУПАТЕЛЬ-ИНН], КПП [ПОКУПАТЕЛЬ-КПП],
именуемое в дальнейшем «Покупатель», в лице директора
[ПОКУПАТЕЛЬ-ФИО-1], с другой стороны, заключили договор
о нижеследующем.
```

Роль определена один раз на профиль (сторону), поэтому один и тот же ИНН
во всём договоре получает один и тот же маркер — обезличенный договор
остаётся читаемым и по нему можно работать. `masked_black.*` — та же
замена, но с чёрной заливкой вместо подсветки, для передачи наружу.

В PDF, где место под маркер ограничено шириной исходного слова, пустоты
вокруг маркера заполняются точками, а не остаются рваным пробелом:
`....[Организация 1]....`.

## Что делает и чего не делает

**Умеет:**

- форматы DOCX, PDF, XLSX; сканированные PDF — через OCR (PaddleOCR/RapidOCR
  за абстракцией `OCRProvider`, дефолт в CI и без extra — `fake`);
- находит ИНН, ОГРН, СНИЛС, паспорт, счета, ФИО, адреса, даты, организации и
  пользовательские типы, описанные предложением на русском языке;
- определяет роли сторон (поставщик/покупатель) и держит маркер одной
  сущности одинаковым по всему документу — см. пример выше;
- маркер по центру освободившегося места вместо чёрного прямоугольника,
  фон подсветки настраивается (`--highlight-background #RRGGBB|none`);
- в XLSX обезвреживает формулы, которые ссылаются на замаскированную ячейку
  (иначе значение восстанавливается арифметикой — самой формулой);
- строит карточку договора: сумма, условия оплаты, срок поставки, ссылка на
  ФЗ — каждый факт с цитатой-источником, якорем на место в документе и
  статусом (`found` / `ambiguous` / `not_found` / `confirmed`);
- выдаёт сертификат обезличивания и отчёт о каждой замене (JSON/HTML);
- задаёт уточняющие вопросы человеку одной пачкой и переживает перезапуск
  процесса на паузе (`interrupt()` графа LangGraph);
- работает офлайн: без LLM продолжает искать реквизиты по контрольным
  суммам и Natasha; вызов модели идёт через отдельный слой `LLMProvider`,
  поэтому смена GigaChat на локальную модель не трогает логику узлов —
  прямое требование заказчика.

**Пока не умеет / не доделано, честно:**

- веб-интерфейс в разработке отдельно (`frontend/`); сейчас продукт
  работает через CLI ([`docs/CLI.md`](docs/CLI.md)) — сквозного
  веб-сценария ещё нет;
- инфраструктура вызова GigaChat готова (провайдер, strict JSON Schema,
  воспроизводимые кассеты ответов для тестов), но прироста метрик от неё
  пока нет: кассеты записаны нейтральными ответами, потому что ключей
  GigaChat в окружении разработки нет — это отдельный шаг при наличии ключа.

## Как это устроено

Движок целиком собран на **LangGraph**: узлы графа делают детекцию,
профилирование, оценку уверенности, паузу на вопросах, план замен и рендер
двух документов из одного плана. Детекция трёхслойная — правила с
контрольными суммами → локальный NER (Natasha) → LLM-арбитр только на
спорном.

```
 extract ─► detect ─► profile ─► judge ─┬─(есть вопросы)─► ask_human ─┐
 (парсер)   (3 слоя)  (субъекты)        │                             │
                                        └────────(нет)────────────────┤
                                                                      ▼
                                                                    plan
                                                                      │
                                       ┌──────────────────────────────┤
                                       ▼              ▼               ▼
                              masked_black.*  masked_highlight.*   report
```

Подробный разбор пайплайна, контрактов и обоснований каждого решения —
[`ARCHITECTURE.md`](ARCHITECTURE.md).

## Принципы, на которых стоит проект

- **Recall важнее precision** для критичных типов (ИНН, паспорт, счета,
  ОГРН, СНИЛС). Пропущенный ИНН — утечка. Лишняя маска — косметика.
- **Утечки нет** — проверяется побайтово по тексту, XML docx/xlsx,
  текстовому слою PDF и метаданным, а не глазами.
- **Не закрашивать поверх живого текста.** Чёрный прямоугольник, под
  которым остался текст, вынимается copy-paste — это худший дефект в этой
  предметной области, и здесь его нет: PDF редактируется через
  `apply_redactions()`, а не заливкой.
- **Никаких выдуманных чисел.** Если для метрики или прогноза нет замера —
  об этом сказано прямо, а не подставлено правдоподобное значение.

Полный список инвариантов и определение готовности задачи — `AGENTS.md`
(`CLAUDE.md` — симлинк на него).
