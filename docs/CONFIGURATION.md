# Конфигурация проекта

Главная точка настройки — [`backend/masker.yaml`](../backend/masker.yaml).
В нём собраны все параметры проекта: приложение, LLM, OCR, путь к GLiNER,
PostgreSQL, MinIO и JWT. Рядом лежит копируемый шаблон
[`backend/masker.example.yaml`](../backend/masker.example.yaml). Комментарии
рядом со значениями объясняют каждое поле.

## Приоритет источников

Для каждого параметра действует один порядок: **переменная окружения → YAML
→ дефолт в коде**. Поэтому контейнеры и CI продолжают настраиваться привычным
окружением, а локальная установка получает один наглядный файл. Явный путь к
другому YAML задаётся `MASKER_CONFIG=/путь/masker.yaml`; если YAML отсутствует,
код просто использует окружение и дефолты.

`.env.example` остаётся нужен: это пример для секретов и развёртывания, а не
второй главный конфиг. Скопируйте его в игнорируемый `.env` или передайте те
же переменные через секрет-хранилище платформы.

```bash
cd backend
cp masker.example.yaml masker.yaml
cp .env.example .env
```

## Секреты

В YAML нет и не должно быть значений ключей и паролей. Поля с суффиксом
`_env` содержат только имя переменной окружения. Например,
`llm.api_key_env: OPENROUTER_API_KEY` означает, что ключ читается из
`OPENROUTER_API_KEY`; `web.database.password_env: POSTGRES_PASSWORD` — что
пароль базы читается из `POSTGRES_PASSWORD`.

То же правило применяется ко всем секретам: LLM-ключам, паролю PostgreSQL,
ключам MinIO и `JWT_SECRET`. Не помещайте их в `masker.yaml`, даже в локальный
файл, исключённый из Git. Это исключает класс ошибки, когда в YAML вместо
имени переменной по ошибке оказывается настоящий ключ.

## Что уже читает код

`masker.llm.get_provider()` берёт активный профиль из `llm.profile` и его
секцию из `llm.profiles`. Профиль объединяет поставщика, модель, таймаут,
параметры конкретного провайдера и тариф. Поэтому для переключения достаточно
сменить одно значение `profile`; модель не сможет случайно получить цену от
другого поставщика. Плоский формат `llm.provider`/`llm.model` остаётся
совместимым со старыми развёртываниями. `MASKER_LLM*` также сохраняют
обратную совместимость и перекрывают YAML.

## Тарифы и расход LLM

У каждого `llm.profiles.<имя>.pricing` есть цены `prompt_per_1k` и
`completion_per_1k`, валюта и обязательная при заданных ценах дата
`verified_at`. Это тарифы за 1 000 токенов. Для каждой модели создайте
отдельный профиль, даже если она ходит через того же поставщика. Тариф
активного профиля можно перекрыть переменными
`MASKER_LLM_PRICING_PROMPT_PER_1K`,
`MASKER_LLM_PRICING_COMPLETION_PER_1K`,
`MASKER_LLM_PRICING_CURRENCY` и `MASKER_LLM_PRICING_VERIFIED_AT`.

Если цены не заданы, отчёт показывает фактически возвращённые моделью токены
и прямо говорит, что стоимость не рассчитана: значение не оценивается по
символам и не подставляется из предположений. Длительности узлов и временная
ось ленты записываются в `runtime-metrics.json` рядом с детерминированным
`report.json`; сам `report.json` содержит безопасную ленту без исходных
персональных данных.

`masker.ocr.select_ocr()` читает `ocr.provider`; `MASKER_OCR` перекрывает
его. `GlinerDetector` читает `models.gliner_path`; его перекрывает
`MASKER_GLINER_PATH`.

Веб-слой читает `application.port` и секцию `web`. Для базы YAML хранит
`host`, `port`, `name`, `user` и имя переменной пароля; при наличии пароля
строится прежний `DATABASE_URL`. MinIO и JWT аналогично получают значения
секретов по указанным именам переменных. Прежние `DATABASE_URL`, `APP_PORT`,
`MINIO_*`, `JWT_*` имеют высший приоритет и не меняют контракт развёртывания.

## Граница слоёв

YAML не делает API обязательным для движка. `masker` не импортирует
`api.core.config`, базу или MinIO и не читает `.env`. Поэтому голый CLI
работает без базы, секретов и самого YAML-файла:

```bash
cd backend
env -u MASKER_CONFIG -u DATABASE_URL -u JWT_SECRET -u MINIO_ENDPOINT \
  -u MINIO_ACCESS_KEY -u MINIO_SECRET_KEY .venv/bin/masker --help
```

Старый узкий LLM-профиль `masker.llm.yaml`, передаваемый через
`--llm-config`, также поддержан для совместимости. Его поля становятся
базой, а переменные окружения всё равно имеют приоритет.
