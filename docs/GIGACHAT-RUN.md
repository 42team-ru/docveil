# Запись живых ответов GigaChat для Д3

Эта операция один раз показывает, как GigaChat определяет жанр документа и
пишет краткое содержание. После неё тесты используют сохранённые ответы и не
требуют сети, ключа или денег.

## Что понадобится

1. В личном кабинете GigaChat создайте ключ авторизации API и скопируйте его
   целиком. Для этого прогона у ключа нужен scope `GIGACHAT_API_PERS`.
2. Откройте терминал в корне репозитория и задайте ключ только для текущего
   окна терминала. Не добавляйте его в `masker.yaml`, кассеты или Git.

```bash
export GIGACHAT_CREDENTIALS='вставьте_сюда_ключ_целиком'
```

## Одна команда на запись

Скопируйте команду целиком из корня репозитория:

```bash
cd backend && .venv/bin/python scripts/record_llm_cassettes.py fixtures/real-contracts/open-contracts/arkhschool-68-183.pdf fixtures/real-contracts/open-contracts/brsc-contract.pdf fixtures/real-contracts/open-contracts/dagestanschool-kais-808.pdf fixtures/real-contracts/open-contracts/eat-654000009321.pdf fixtures/negative/negative_01_gost.docx --llm gigachat-max
```

Скрипт обрабатывает только эти пять документов, а не весь корпус. Он делает
локальные детекцию и сбор полей договора, а к GigaChat обращается только за
типом документа и пересказом первой страницы. В запросе от 11.09.2026 поле
`kind` обязательно и принимает только `contract`, `non_contract` или
`unknown`. Для `non_contract` поле `genre` выбирается строго из списка:
договор, техническое задание, технические условия / стандарт, устав, счёт,
акт, приказ, доверенность, письмо, отчёт, иное. Для `иное` обязательна
короткая (до 80 символов) конкретизация в `genre_detail`; для остальных
жанров она равна `null`.

Это **третья перезапись**: изменение закрытого списка и JSON-схемы намеренно
меняет ключ каждого запроса. Старые пять кассет от 11.09.2026 не проверяют
новый enum, краткость `genre_detail` и корректную карточку ГОСТа, поэтому не
подходят. Запустите команду для всех пяти документов; не редактируйте кассеты
вручную и не меняйте промпт ради старого хеша. До записи соответствующие
офлайн-сценарии будут пропущены с этой причиной.

## Что появится после успеха

- `backend/fixtures/llm/summary/summary-*.json` — кассеты ответов GigaChat.
  Это данные для офлайн-тестов; их нужно просмотреть и добавить в следующий
  коммит вместе с результатом записи.
- `backend/out/llm-summary-cassettes/cards.md` — карточки для чтения глазами.
  В них есть исходные названия и цитаты, поэтому файл локальный: не
  пересылайте его и не коммитьте.
- В терминале — число новых/повторно использованных кассет, входные и
  выходные токены, а также рассчитанная стоимость.

Откройте `cards.md` и проверьте:

- пересказ соответствует именно этому документу, а не придуман;
- стороны названы в точности как в исходнике, без склонения названий и ФИО;
- у четырёх договоров тип — `contract`;
- на `negative_01_gost.docx` указан не договор и назван жанр, а ниже явно
  сказано, что поля договора не собирались.
- у `brsc-contract.pdf` номер протокола не выдан за номер контракта, а
  заказчик и исполнитель приведены полностью из преамбулы;
- в цене нет штрафа, в поставке нет сроков приёмки/претензии, а каждый ФЗ
  имеет номер и не повторяется.

## Стоимость

Профиль `gigachat-max` в `backend/masker.yaml` хранит тариф на 10.09.2026:
0,096 ₽ за 1 000 входных токенов и 0,289 ₽ за 1 000 выходных. В Д3 в модель
уходит только первая страница (не больше 6 000 символов), поэтому пять
документов ориентировочно стоят **около 1 ₽** (порядок — единицы рублей), а
не стоимость обработки полного корпуса. Точную сумму не оценивайте вручную: скрипт печатает её по
фактическому `usage`, который вернул GigaChat.

## Если запрос не проходит

**TLS.** В `masker.yaml` для профиля `gigachat-max` уже включён
`insecure_skip_tls_verify: true`: это осознанная настройка для корпоративного
прокси с самоподписанным корнем. Скрипт использует её автоматически. Не
отключайте проверку TLS дополнительными флагами и не меняйте конфиг ради
этого прогона. Если ошибка TLS осталась, сохраните её текст и передайте
администратору сети: вероятно, прокси недоступен или изменил цепочку.

**Истёк токен / нет авторизации.** GigaChat получает OAuth-токен заново из
`GIGACHAT_CREDENTIALS`. Получите новый ключ или заново скопируйте действующий
в переменную окружения, затем повторите ту же команду. Скрипт не записывает
секрет на диск.

## Закрепить результат без сети

После проверки карточек запустите из `backend`:

```bash
.venv/bin/python -m pytest tests/masker/summary/test_summary_cassettes.py -q
```

Этот тест использует только `CassetteProvider`: отключённая сеть и отсутствие
`GIGACHAT_CREDENTIALS` ему не мешают. Пока нет кассеты для текущего промпта,
конкретный сценарий пропускается с понятной причиной; после записи включится
сам. Перед коммитом проверьте, что
в индекс попадут кассеты из `fixtures/llm/summary/`, но не локальный каталог
`out/llm-summary-cassettes/`.
