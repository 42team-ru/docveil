# 1. Цель T1.13

T1.13 открывает таксономию типов сущностей.

Ранее:

* `EntityType` — закрытый `StrEnum`;
* `Entity.type` имел тип `EntityType`;
* пользовательские типы невозможно было создавать без изменения enum.

Целевое состояние:

* `EntityType` остаётся enum встроенных типов;
* `Entity.type` становится `str`;
* появляется `EntityTypeRegistry`;
* built-in и custom типы описываются через `EntityTypeSpec`;
* пользователь описывает тип естественным языком;
* LLM-компилятор через `LLMProvider` компилирует описание в `CustomTypeSpec`;
* custom type исполняется одним из executor'ов;
* GLiNER2 используется только для пользовательских semantic типов;
* Natasha остаётся детектором built-in `person` / `org_name`.

Архитектурные решения уже приняты и не должны переоткрываться без необходимости.

## Шаг 1 — EntityTypeRegistry

Этот шаг уже закоммичен:

```text

```

Реализованы:

```text
src/masker/entity_types.py
tests/masker/test_entity_types.py
```

Основные сущности:

```python
@dataclass(frozen=True, slots=True)
class EntityTypeSpec:
    id: str
    title: str
    marker_label: str
    critical: bool = False
    builtin: bool = True
```

и:

```python
class EntityTypeRegistry:
    def __contains__(self, type_id: str) -> bool
    def spec(self, type_id: str) -> EntityTypeSpec
    def ids(self) -> tuple[str, ...]
    def critical_ids(self) -> frozenset[str]
    def extend(self, custom: Iterable[EntityTypeSpec]) -> EntityTypeRegistry

    @classmethod
    def builtin(cls) -> EntityTypeRegistry
```

Тесты для этого шага включают:

* совпадение built-in registry с `EntityType`;
* иммутабельность `extend`;
* совпадение critical типов с `CRITICAL_TYPES`.

## detect/agent.py

Детектор должен работать с registry.

Конструктор должен принимать примерно:

```python
registry: EntityTypeRegistry | None = None
```

Проверка допустимого типа должна использовать registry:

```python
entity.type in self._registry
```

```python

```

и заменить их на:

```python
entity.type
```

Все сравнения типов должны быть строковыми.
