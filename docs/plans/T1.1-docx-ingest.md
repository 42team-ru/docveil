   получаем `p.text = "Почта: info@triema.example — пишите."` (35 симв.) и
   `"".join(r.text for r in p.runs) = "Почта:  — пишите."` (17 симв.). Наивная реализация
   на `p.runs` теряет e-mail целиком, реализация на `p.text` без единого определения
   последовательности run'ов даёт рендеру смещения, которые не сходятся с его обходом,
   — то есть замену не того куска текста. И то и другое — утечка.

## 3. Решения по контрактам

### 3.1 Что возвращаем в `src/masker/model.py`

Ровно пять имён, каждое имеет потребителя **сегодня**:

```python
class Source(StrEnum):
    RULE = "rule"   # регулярка + контрольная сумма
    NER = "ner"     # локальная модель
    LLM = "llm"     # арбитр


@dataclass(frozen=True, slots=True)
class Anchor:
    """Место сегмента в исходном файле. Наружу — непрозрачный ключ:
    сравнивать можно, разбирать — только адаптеру своего формата."""
    fmt: str                      # "docx" | "xlsx" | "pdf"
    locator: tuple[str | int, ...]  # docx: ("body", para_idx)
    label: str = ""               # «абзац 7» — для отчёта человеку


@dataclass(slots=True)
class Segment:
    """Непрерывный кусок текста документа с якорем."""
    text: str
    anchor: Anchor
    order: int                    # плотная позиция в линейном обходе, 0..N-1


@dataclass(slots=True)
class Entity:
    """Найденная сущность: что, где, кем найдено, насколько уверенно."""
    type: EntityType
    text: str                     # исходное значение как в документе
    segment_order: int
    start: int                    # смещения внутри Segment.text, [start, end)
    end: int
    source: Source
    confidence: float = 1.0
    normalized: str = ""          # ключ согласованности, заполняет детектор


@dataclass(slots=True)
class Document:
    """Разобранный документ — то, с чем работают все агенты после Ingest."""
    path: str
    fmt: str
    segments: list[Segment]
    meta: dict[str, str] = field(default_factory=dict)

    def text(self) -> str:
        """Линейный текст документа — вход для NER и LLM."""
        return "\n".join(s.text for s in self.segments)
```

Что из удалённого коммитом `9068c01` **не возвращаем** и когда вернётся:

| имя | вернётся в | почему не сейчас |
|---|---|---|
| `Party`, `Profile` | T1.4 (роли — T3.2) | нет ни одного потребителя в `src/` и `tests/` |
| `Entity.party`, `Entity.profile_id` | T1.4 | поля, которые никто не заполняет и не читает |
| `Entity.key` | T1.6 | ключ согласованности маркеров — предмет T1.6 |
| `Entity.id` (blake2s) | T1.5 | адресат ответа человека появляется вместе с вопросами |
| `Source.USER` | T1.5 | подтверждение человеком возникает вместе с `ask_human` |
| `MaskStyle`, `Replacement`, `Question`, `MaskResult` | T1.7 / T1.5 / T1.9 | `eval.py` обращается к ним только через `masker.pipeline`, импорт которого обёрнут в `try/ImportError` — ворота от их отсутствия не краснеют |
| `Document.ocr_used` | T2.3 | OCR-ветки нет |
| `Document.parties` | T3.2 | ролей нет |
| `Anchor.page` | T2.2 | для docx бессмысленно; страница для PDF ляжет в `locator`/`label` |

`Anchor.locator` типизируем `tuple[str | int, ...]`, а не `tuple[Any, ...]`:
под mypy strict `Any` молча отключает проверку в самом чувствительном месте —
в адресе, по которому потом будет вырезаться текст. Для docx («body», int) и
xlsx («Смета», «D14») этого достаточно; T2.2 расширит объединение на `float`
ради bbox — расширение union'а потребителей не ломает.

### 3.2 Форма якоря: почему `("body", para_idx)`, а не `(part, para_idx, run_idx)`

`TASKS.md` требует `(part, para_idx, run_idx)`, `ARCHITECTURE.md` —
`(part, para_idx, run_idx, char_range)`. Это противоречие с самой конструкцией
«сегмент = абзац», и разрешать его надо явно.

- `Segment` — абзац, `Entity.start/end` — смещения **внутри текста абзаца**.
  `char_range` уже есть, он живёт в `Entity`, а не в якоре; дублировать его в
  якоре означает два источника истины об одном и том же.
- Сущность **может пересекать границу run'ов**: Word режет абзац на run'ы по
  форматированию, орфографии и правкам, и «ИНН 3662103003» реально приезжает
  как `«ИНН 36»`, `«62»`, `«103003»`. Одно число `run_idx` такую сущность не
  адресует в принципе. Именно поэтому T1.7 в формулировке «run разрезается на
  три» всё равно обязан **вычислять** набор run'ов по смещениям — то есть
  `run_idx` в якоре не используется даже там, ради чего его вводили.
- Ingest не знает, где начнётся сущность: он видит абзац раньше детектора.
  Записать в якорь «run сущности» на этапе ingest физически нельзя.

**Решение:** `locator = ("body", para_idx)`, `label = "абзац N"` (1-based).
`part` в первом элементе остаётся — это дискриминатор, по которому T1.11/T1.12
добавят `("table", tbl, row, col, para)` и `("header", section, para)`, ничего
не меняя в уже выданных якорях и в диспетчере рендера.

Разрешение run'ов — функция рендера, и её вход определяется здесь, в T1.1:
`docx_ingest.iter_runs(paragraph)` (см. 3.3). T1.7 получит по якорю абзац,
позовёт `iter_runs`, накопительно сложит длины и найдёт run'ы, покрывающие
`[start, end)`. Это работает и для одного run'а, и для трёх, и для гиперссылки.

Альтернатива, которую отвергаем: оставить `run_idx = 0` как заглушку. Поле,
которое ничего не адресует, — это приглашение написать на него `if`, а на
защите вопрос «что если ИНН в двух run'ах» останется без ответа.

Последствие решения: правится текст `TASKS.md` T1.1 и строка DOCX в таблице
якорей `ARCHITECTURE.md` (точный текст — §8).

### 3.3 Текст сегмента: что именно склеивается

**`Segment.text` посимвольно равен `paragraph.text`** — никакого `strip()`,
схлопывания пробелов, замены неразрывного пробела, нормализации регистра.
Причина жёсткая: `Entity.start/end` — индексы в этой строке, и рендер по ним
режет run'ы. Любая нормализация сдвигает смещения и приводит к вырезанию
соседнего текста при оставленной на месте сущности — это утечка, которую
не видно ни в одном тесте, кроме посимвольного.

Одновременно вводится определение канонической последовательности run'ов:

```python
def iter_runs(paragraph: Paragraph) -> list[Run]:
    """Runs абзаца в порядке документа, включая runs внутри гиперссылок.

    `paragraph.runs` отдаёт только прямых детей `w:p` и теряет текст
    гиперссылок, а `paragraph.text` их включает. Единственная форма, при
    которой смещения сегмента совпадают с обходом рендера, — эта.
    """
```

Инвариант, который проверяется тестом:
`"".join(r.text for r in iter_runs(p)) == p.text == segment.text`.
Он держится потому, что `CT_P.text` определён ровно как склейка `w:r | w:hyperlink`
в порядке документа (проверено по исходнику python-docx 1.2.0).

Ниже — прочие решения по тексту:

| случай | решение | почему |
|---|---|---|
| абзац пустой или только пробелы (`not text.strip()`) | сегмент не создаётся | маскировать нечего; `order` должен оставаться плотным |
| двойные пробелы, табы (`\t`), мягкие переносы (`\n` от `w:br`) | оставляем как есть | это содержимое `p.text`, смещения важнее косметики |
| несколько run'ов в абзаце | склеиваются встык, без разделителей | иначе «ИНН 36»+«62103003» не найдётся регуляркой |
| текст гиперссылки | входит в сегмент, run внутри `w:hyperlink` входит в `iter_runs` | e-mail и сайт в тендерных документах почти всегда гиперссылки |
| `w:fldSimple`, `w:smartTag`, `w:ins/w:del` | не попадают ни в `p.text`, ни в `iter_runs` | известное слепое пятно, зафиксировано в рисках (§7), отдельная задача |
| нечитаемый/не-docx файл | исключение python-docx наружу, не глушим | `except Exception: pass` запрещён правилами |

### 3.4 `Segment.order` против `para_idx`

Две разные величины, и их нельзя путать:

- `Segment.order` — плотная нумерация 0..N-1 по порядку чтения. Её использует
  `rules.find_biks` / `_nearby_biks` (соседство ±3 сегмента), на неё опирается
  восстановление смещений в NER-спайке. Дырка в `order` тихо сломает поиск БИК
  рядом со счётом.
- `para_idx` в якоре — физический индекс абзаца в `doc.paragraphs`. В нём дырки
  есть и должны быть: пропущенные пустые абзацы физически существуют, и рендер
  обязан находить абзац по индексу, а не по счётчику непустых.

### 3.5 `is_table` — убираем

Убираем поле из `Segment`. Аргументы:

1. В скоупе T1.1 его некому выставить в `True` — это поле-константа `False`.
   Ветка логики, которую нельзя покрыть тестом, — это ветка, которой нет.
2. Когда таблицы вернутся (T1.11), признак «это ячейка» уже выражен якорем:
   `anchor.locator[0] == "table"`, и там же лежит адрес строки и столбца,
   который булеву флагу недоступен. Флаг был бы вторым, менее полным источником
   истины о том же самом.

Цена: правка `tests/test_rules.py` — 6 конструкторов `Segment(..., is_table=False)`.
Механическая, и она всё равно входит в работу по позеленению ворот.

### 3.6 `Document.meta`

Кладём только непустые строковые `core_properties`: `author`, `last_modified_by`,
`title`, `subject`, `comments`, `category`, `keywords`. Даты (`created`,
`modified`) и `revision` не кладём — `meta: dict[str, str]`, а лезть в него
`datetime` не должен; для отчёта они не нужны, а зачистка метаданных в T1.7
делается по всему набору свойств независимо от содержимого `meta`.

Метаданные **не становятся сегментами** в T1.1. Автор «Петрова Мария Сергеевна»
— это PERSON, и вопрос «детектим ли мы по meta» реальный, но он относится к
T1.2/T1.8: T1.7 обязан зачистить `docProps` целиком, поэтому утечки через meta
не будет и без детекции. Здесь фиксируем это явно, чтобы никто не считал,
будто ingest уже решил вопрос.

## 5. Детерминизм

Источников недетерминизма в T1.1 три, и все закрыты:

1. **Порядок обхода.** `doc.paragraphs` — порядок XML-детей `w:body`, он
   определён файлом. `Segment.order` — счётчик добавленных сегментов, не
   зависит ни от чего внешнего. Никаких `set`/`dict`-итераций в формировании
   списка сегментов быть не должно — это отдельный пункт ревью.
2. **`meta`.** Собирается из фиксированного кортежа пар, порядок вставки
   воспроизводим; сравнение в тесте — по словарю, не по `repr`.
3. **Хеш-рандомизация.** Проверяется `test_ingest_is_deterministic`:
   подпроцесс с `PYTHONHASHSEED=1` даёт тот же список `(order, locator, text)`,
   что и текущий процесс. Если когда-нибудь порядок сегментов начнёт зависеть
   от обхода множества, этот тест покраснеет.

`random` в T1.1 не появляется вовсе.

**A. Форма якоря.** `TASKS.md`/`ARCHITECTURE.md` требуют `run_idx`, конструкция

### 10.1 Воспроизводимый helper для гиперссылки в тесте

В `tests/test_docx_ingest.py` добавить импорты:

```python
from docx.opc.constants import RELATIONSHIP_TYPE as RT
from docx.oxml import OxmlElement
from docx.oxml.ns import qn
from docx.text.paragraph import Paragraph
```

и локальный helper:

```python
def append_hyperlink(paragraph: Paragraph, text: str, url: str) -> None:
    relation_id = paragraph.part.relate_to(url, RT.HYPERLINK, is_external=True)
    hyperlink = OxmlElement("w:hyperlink")
    hyperlink.set(qn("r:id"), relation_id)
    run = OxmlElement("w:r")
    text_element = OxmlElement("w:t")
    text_element.text = text
    run.append(text_element)
    hyperlink.append(run)
    paragraph._p.append(hyperlink)
```

После `doc.save(path)` открыть файл заново перед вызовом `ingest_docx`: тест
тогда проверяет реальный DOCX, а не только объект в памяти.

Для `test_ingest_never_reads_headers_or_footers` использовать
`from unittest.mock import patch` и `from docx.section import _BaseHeaderFooter`:

```python
with patch.object(
    _BaseHeaderFooter,
    "_get_or_add_definition",
    side_effect=AssertionError("ingest не должен читать колонтитул"),
):
    ingest_docx(path)
```
