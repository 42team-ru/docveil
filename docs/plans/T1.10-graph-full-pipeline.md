# T1.10 — Сборка графа: plan → render → validate → report

Ветка: `feat/graph-plan-render-validate`.

T1.5.1 уже дал `StateGraph`, `SqliteSaver`, паузу и durable resume. Здесь
достраивается хвост конвейера и разгружается `src/masker/cli.py` (1204 строки),
где сегодня руками собран второй, параллельный графу пайплайн
(`inspect_docx`, `inspect_pdf`, `_write_graph_report`).

## 0. Границы, заданные заказчиком (не обсуждаются)

1. **HTML-отчёт в граф не выносится.** `src/masker/report/html.py` остаётся
   вызовом на стороне вызывающего: он скоро заменяется отрисовкой в React.
   Граф про HTML не знает вообще.
2. **`cli.py` — временный вызывающий.** Через него скоро придёт веб/API.
   Значит после T1.10 в `cli.py` остаётся только: разбор аргументов, проверка
   их сочетаний, сборка `LLMProvider`, вызов `masker.run`, запись
   `report.json`/`questions.json`/`report.html`, печать и коды возврата.
   Ни одной предметной операции (детекция, план, рендер, валидация, сборка

3. Инварианты `AGENTS.md`: детерминизм, отсутствие утечек, идемпотентность,

## 1. Что есть сегодня (факты по дереву, не по памяти)

- `graph/build.py`: `extract → detect → profile → judge → policy →
  (ask_human) → apply_answers → finalize → END`. Узлы `plan`/`render`/
  `validate`/`report` отсутствуют.
- `graph/nodes.py::extract_node` жёстко зовёт `ingest_docx` — PDF через граф
  не проходит.
- `profile_node`/`judge_node` выполняются **всегда**, `options["profile"]`
  никем не читается (в `RunOptions` поле есть и входит в `thread_id`).
- `finalize_node` кладёт `final_actions` и `decisions` — и на этом граф
  заканчивается. Артефактов граф не производит: `_write_graph_report`
  честно пишет в докстринге «настоящий masked_black/masked_highlight
  графовый путь пока не производит — это T1.10».
- `cli.py` содержит два независимых конвейера с почти одинаковым, но
  расходящимся кодом сборки `report.json`: `inspect_docx` (простой путь,
  умеет `--redact-style` + Validate) и `_write_graph_report` (графовый путь,
  умеет `decisions`, но не умеет рендер и всегда пишет
  `validation.status = "skipped"`).
- `masker/eval.py` зовёт агентов напрямую и от `cli.py` не зависит — ворота
  метрик от этой задачи не ломаются механически (но могут поехать по существу,
  см. риск R1).

## 2. Целевой граф

```
extract → detect → profile → judge → policy ─┬─ ask_human ─┐
                                             └─────────────┤
                                                           ▼
                                        apply_answers → finalize
                                                           ▼
                                     plan → render → validate → report → END
```

Все четыре новых узла — безусловные, без ветвлений. Ветвление «рендерить или
нет» намеренно не вводится: набор произведённых артефактов должен зависеть
только от опций прогона, а не от данных документа (пустой план — это копии
без замен, а не отсутствие файлов). Единственная развилка графа остаётся
одна — `needs_human`.

### Разделение труда по узлам

| Узел | Делает | Пишет в State |
|---|---|---|
| `extract` | ingest по формату + покрытие документа | `fmt`, `segments`, `meta`, `coverage` |
| `detect` | детекция + покрытие детекторами | `entities`, `detection_coverage` |
| `plan` | `PlanAgent.plan(...)` с `actions` из `final_actions` | `plan` |
| `render` | оба рендера + preview, запись файлов в `deps.artifact_dir` | `artifacts` |
| `validate` | `ValidateAgent.validate(plan, редактирующие артефакты)` | `validation`, `leaked` |
| `report` | сборка отчётной структуры из State (чистая функция) | `report` |

`coverage` и `detection_coverage` считаются там, где уже есть нужные объекты
(открытый zip/pdf и собранный `DetectAgent`), а не в `report`: иначе
`report_node` пришлось бы заново открывать файл и заново конструировать
`DetectAgent()` (то есть поднимать Natasha) только ради двух словарей.

## 3. Граница «узел — run.py — cli.py»

**В узлы графа** переезжает: разбор PDF (`extract`), покрытие документа,
покрытие детекторами, построение плана, оба рендера + preview, валидация,
сборка полной отчётной структуры (сегодняшний контент `report.json`).

**В `run.py`** переезжает: `artifact_dir` как зависимость прогона, тонкие
аксессоры результата (`report_of(outcome)`, `artifacts_of(outcome)`) и
трансляция сбоев узлов в доменное исключение `RunFailedError`.

**В `cli.py`** остаётся: argparse и проверки сочетаний флагов, загрузка
конфига LLM и `TracingProvider`, вызовы `start_run`/`resume_run`, запись
`report.json`, `questions.json`, `report.html`, `llm-trace.*`, печать и коды
возврата (`0`, `2`, `3`, `4`, `10`).

**Почему бинарные артефакты пишет узел, а JSON — вызывающий.** Рендер — это
и есть запись файла: `python-docx` и `pymupdf` сохраняют документ сами,
возвращать «байты docx» из узла — выдумывать промежуточный формат ради
симметрии. А `report.json` — сериализация структуры, которая целиком лежит
в `state["report"]`: веб-клиент возьмёт её из State и в файл писать не станет.
Граница проходит ровно здесь и в плане больше нигде не размывается.

## 4. Новые поля `State` и их JSON-совместимость

Всё, что попадает в `State`, проходит через msgpack-сериализацию
чекпойнтера. Правила (те же, что уже соблюдает `graph/serde.py`):

- никаких `Path`, `frozenset`, `Enum`, датаклассов — только `str`, `int`,
  `float`, `bool`, `list`, `dict`, `None`;
- кортежи не использовать как «кортежи»: после round-trip через чекпойнтер
  они приходят списками, код обязан быть к этому безразличен;
- ключи словарей — только строки.

| Поле | Тип | Содержимое |
|---|---|---|
| `coverage` | `dict[str, Any]` | сегодняшний `document_coverage` (docx или pdf-вариант) |
| `detection_coverage` | `dict[str, list[str]]` | сегодняшний `_detection_coverage` |
| `plan` | `dict[str, Any]` | сериализованный `MaskPlan` (новые `plan_to_dict`/`plan_from_dict` в `graph/serde.py`) |
| `artifacts` | `list[dict[str, str]]` | `{"role": ..., "name": ..., "path": ..., "redacting": bool}` |
| `validation` | `dict[str, Any]` | `{"status": "checked"/"skipped", ...}` — формат сегодняшних `_validation_record`/`_validation_skipped` без изменений |
| `leaked` | `list[dict[str, Any]]` | `dataclasses.asdict(Leak)` |
| `report` | `dict[str, Any]` | ровно то, что сегодня пишется в `report.json` |

`role` ∈ `{"preview", "masked_highlight", "masked_black"}`. `path` —
абсолютный путь строкой (нужен CLI для печати и валидатору), `name` — только
имя файла.

**В `report` абсолютных путей быть не должно** — ни одного. Сегодняшний
`test_two_cli_runs_give_byte_identical_report` гоняет два прогона в разные
`--out` и сравнивает `report.json` побайтово: попадание `path` в отчёт
уронит этот тест, и правильно сделает. В отчёт идут только `name`.

### Опции прогона: что в State, что в deps

Правило, которое дальше не нарушается: **что граф делает — в
`State["options"]`; куда он это кладёт — в `RunDeps`.**

- `RunOptions` (State, участвует в `thread_id` через `canonical()`): без
  изменений — `types`, `rules_only`, `profile`, `unmask_critical`,
  `llm_config_id`.
- `RunOptions` новые поля **вне** `canonical()`: `styles: tuple[str, ...]`
  (подмножество `("marker", "blackbox")`, по умолчанию пустое) и
  `preview: bool = True`. В `thread_id` они не входят: они не меняют отбор
  PII, и повторный `--ask` того же документа обязан попадать в тот же тред
  независимо от того, какие артефакты попросили на выходе. В
  `_initial_state` они кладутся в `state["options"]` рядом с `thread_id` и
  `interactive`.
- `RunDeps` новое поле: `artifact_dir: Path | None = None` — каталог, куда
  `render_node` пишет файлы. Не в State: `Path` не JSON, каталог не влияет на
  идентичность прогона, и при `--resume` вызывающий обязан иметь право
  указать другой каталог, не мутируя чекпойнт. `render_node` при
  `artifact_dir is None` бросает `ValueError` — не «тихо ничего не рендерит».
  Тихий пропуск здесь — прямой путь к «граф отработал, файлов нет, а никто
  не заметил».

Следствие для `--resume`: стили и preview берутся из чекпойнта первой фазы
(CLI-флаги стилей при `--resume` игнорируются — это надо явно написать в
help), а каталог — из текущего вызова.

## 5. Поведение при ошибках

- Узлы **ничего не глотают**: `except Exception: pass` запрещён `AGENTS.md`,
  и здесь особенно — «рендер не смог» обязано быть провалом, а не тихим
  отсутствием маски.
- `render_node`: `OSError` (нет каталога, нет прав, диск), `ValueError`
  (неизвестный стиль, отсутствует `artifact_dir`) — наружу как есть.
- `validate_node`: **найденные утечки — это не исключение.** Узел кладёт
  `leaked` в State и завершается успешно; провалом прогона это становится
  на уровне вызывающего (код возврата 4), потому что граф обязан довести
  прогон до `report` — иначе диагностику утечки негде взять.
- `run.py` оборачивает `graph.invoke` и превращает `OSError`/`ValueError` из
  узлов в `RunFailedError(thread_id, node_hint, cause)`; `cli.py` печатает
  его в stderr и возвращает код `5` (новый; `4` занят утечкой).
- Тред после сбоя остаётся незавершённым: `start_run` на нём даст
  `ThreadExistsError`/повторный старт по правилам T1.5.1, чинится `--fresh`.
  Это осознанно: молча дописывать в поломанный тред хуже.

## 6. Детерминизм: где он может утечь

1. `by_locator`/`buckets` — обычные `dict`, порядок вставки; вход
   (`plan.replacements`) уже в текстовом порядке — не трогать.
2. `artifacts` строится по фиксированному списку ролей в фиксированном
   порядке (`preview`, `masked_highlight`, `masked_black`), а не по обходу
   множества стилей.
3. `ValidateAgent` уже сортирует `leaked`/`residual`/`checked_parts` —
   ничего не досортировывать поверх, но и не терять сортировку при переносе
   в `validation`/`leaked` State.
4. `report` сериализуется в `cli.py` с `sort_keys=True` — как сегодня.
5. Ни `time`, ни `uuid`, ни `random`, ни `id()` в новых узлах. `id(entity)`
   сегодня используется в `_entity_record` как ключ отображения
   `ref_by_entity_id` — при переносе в `report/payload.py` он должен
   остаться **локальным** ключом внутри одного вызова (никогда не попадать
   в вывод).
6. Байты `.docx` сравнивать нельзя (`python-docx` штампует время в заголовки
   zip) — сравнивается распакованное содержимое частей, как уже сделано в
   `test_determinism.py`.

`validation = {"status": "skipped", "reason": "preview_only: --redact-style не задан"}`

Файлы: `src/masker/graph/nodes.py`, `src/masker/graph/build.py`.

## 9. Решения и альтернативы

**Р1. Имена артефактов.** Выбрано: `masked_highlight.*` / `masked_black.*`
(имена из `ARCHITECTURE.md`), `redacted.docx` retired, `--redact-style`
получает вариант `both`. Альтернатива — сохранить `redacted.docx` и не
трогать три теста; отвергнута: два стиля в один файл не помещаются, а
инвариант `AGENTS.md` говорит про **оба** документа. Сделать `both`
поведением по умолчанию — отдельный шаг (T1.9), здесь дефолт не меняется,
чтобы `make demo` и корпусные прогоны не поменяли состав выхода внутри
задачи про сборку графа.

**Р2. Узел `report` против сборки отчёта в `run.py`.** Выбран узел:
заказчик просит структуру в State, чтобы React/API брали её без CLI; узел
даёт её в чекпойнте, то есть переживает перезапуск. Альтернатива (собирать
в `run.py`) дешевле на один узел, но структура тогда не сохраняется и после
падения процесса её негде взять.

**Р3. `artifact_dir` в `RunDeps`, а не в State.** Альтернатива — положить в
`state["options"]` и мутировать через `graph.update_state` при `--resume`.
Отвергнута: лишняя запись в чекпойнт на приостановленном треде трогает
`_thread_status` и семантику `interrupts`, ради параметра, который не влияет
ни на одно решение графа.

## 10. Что может пойти не так

**R1 — просадка recall на непрофильном пути.** Сегодня `inspect_docx`
строит план с `actions=None` (маскируется всё), а графовый путь применяет
`final_actions` из `PolicyAgent.apply`. После объединения путей вердикт
судьи с низкой уверенностью может дать `KEEP` там, где раньше была маска.
Обнаружение: `masker.eval --gate` (порог recall 1.0 по критичным типам,
`critical_unmasked == 0`) плюс новый тест «неинтерактивный прогон без
`--profile` маскирует все найденные сущности» (`skipped.by_reason` не
содержит `kept`). Если поедет — правильная реакция не «поднять порог», а
не применять `final_actions` при `options.profile is False`.

**R2 — monkeypatch рендера в тестах перестаёт попадать в цель.** Узел
импортирует `render_docx_redacted` по имени модуля; если импортировать
функцию в `nodes.py` напрямую (`from ... import render_docx_redacted`),
патч `docx_redact_module.render_docx_redacted` перестанет действовать, и
тест на утечку **тихо позеленеет**, перестав что-либо проверять.
Обнаружение: `make gate-selftest` и явная проверка внутри теста, что
подменённый рендер действительно вызвался (счётчик вызовов).

**R3 — размер чекпойнта.** В State теперь и `plan`, и `report`, и
`segments` — полный текст документа плюс два его производных. На больших
файлах sqlite-чекпойнт растёт. Обнаружение: замер размера `state.sqlite`
после прогона корпуса в `make demo`; порог — вопрос T2.x, здесь только
зафиксировать число в отчёте о выполнении.

**R4 — `--resume` в другой `--out`.** Стили приходят из чекпойнта, каталог —
из вызова. Человек, указавший при resume другой `--out`, получит артефакты
там, а `questions.json` первой фазы останется в старом каталоге.
Обнаружение: тест «resume с другим `--out` кладёт `report.json` и оба
`masked_*` в новый каталог и ничего не пишет в старый».

**R5 — PDF через граф.** `ingest_pdf` даёт другие якоря; `ProfileAgent` на
PDF не проверялся. Смягчение: CLI для PDF выставляет `profile=False` и
`interactive=False`; тест «PDF-прогон через граф даёт `profile_judge`
отсутствующим и непустой `entity_count`». Если `ProfileAgent` на PDF всё же
позовут — это будет видно как падение теста 3 шага 3.

**R6 — «граф отработал, файлов нет».** Единственная защита — `ValueError`
при `artifact_dir is None` и тест 3 шага 5. Никаких «если каталога нет,
пропустим рендер».
