# T1.13 — Реестр типов сущностей и пользовательские типы

## Context

`EntityType` — закрытый `StrEnum` в `model.py`. Пользовательский тип (напр. «даты отгрузки»)
нельзя вписать в enum на этапе кода. T1.13 открывает таксономию: `Entity.type` становится
`str`, появляется `EntityTypeRegistry`, LLM-компилятор превращает словесное описание в
исполнимый `CustomTypeSpec`, GLiNER2 (`fastino/gliner2.5-multi-v1`) — новый детектор для
пользовательских семантических типов. Natasha остаётся для built-in типов.

## Ответы на открытые вопросы (из design notes §6)

| Вопрос | Решение |
|--------|---------|
| LLM компилятора | GigaChat-Max через LLMProvider |
| Формат preview_matches | `{segment_text, matched_text, start, end}` × N |
| Partial success | compiled[] + errors[], не fail-fast |
| Ретрай ask | max 3 раунда, потом cannot_compile |
| Cache спеков | не в T1.13 |
| Combo B | отдельная T1.13.1 |
| Тестовая фикстура | адаптировать contract_pdf_02_school.labels.json |
| critical: true | разрешить с предупреждением |

## Шаг 4 — GlinerModel + CustomDetector

**Новый файл:** `src/masker/detect/gliner.py`

```python
class GlinerModel:
    """Обёртка над GLiNER2. Ленивая загрузка, import gliner только внутри __init__."""
    
    def __init__(self, model_id: str = "fastino/gliner2.5-multi-v1") -> None
    
    def extract_label(
        self, text: str, label: str, description: str, threshold: float
    ) -> list[tuple[int, int, str]]   # (start, end, matched_text)
    
    def extract_structure(
        self, text: str, fields: Sequence[FieldDef], threshold: float
    ) -> list[tuple[int, int, str, str]]   # (start, end, matched_text, field_name)
```

Ключевые детали:
- `torch.set_num_threads(1)` при инициализации (детерминизм)
- `model.eval()` после загрузки
- `_spans_from_label_texts(label_to_texts, text)` — порт из `spikes/gliner_ru/run_spike.py` (find + Counter для дублей)
- Structure API: `create_schema().structure(name).field(name, dtype, description)...`
- Тесты: `@pytest.mark.models` + `pytest.importorskip("gliner")`

**Новый файл:** `src/masker/detect/custom_detector.py`

```python
class CustomDetector:
    name = "custom"
    source = Source.USER
    priority = 95   # < RULE(100), > NER(50)
    
    def __init__(
        self,
        specs: Sequence[CustomTypeSpec],
        gliner_model_id: str = "fastino/gliner2.5-multi-v1",
        llm: LLMProvider | None = None,
    ) -> None
    
    @cached_property
    def _gliner(self) -> GlinerModel   # ленивая инициализация
    
    @property
    def types(self) -> frozenset[str]  # frozenset({spec.id for spec in specs})
    
    def detect(self, document: Document) -> list[Entity]
```

Dispatch по `spec.executor.kind`:
- `literals` → `re.escape` значений, сортировка по убыванию длины, alternation, `(?<!\w)…(?!\w)` при `whole_word`
- `regex` → скомпилированный паттерн, `finditer` по сегментам; если `context_words` — проверка в окне ±`window`
- `regex_context` → то же с обязательным `context_words`
- `gliner_label` → `self._gliner.extract_label(text, label, description, threshold)` по сегментам
- `gliner_structure` → `self._gliner.extract_structure(text, fields, threshold)` по сегментам
- `regex_llm_filter` → regex-кандидаты → batch LLM-вызов (один вызов на сегмент) → фильтр

Бюджет: `perf_counter` накапливает время regex-прогонов; при > 2.0 с → `CustomTypeError(type_id, "budget exceeded")`.

confidence: `1.0` для literals, `0.9` для regex/regex_context, из threshold для gliner_*, `0.9` для regex_llm_filter.

## Шаг 5 — LLM-компилятор

**Новая директория:** `src/masker/compile/`

**`src/masker/compile/agent.py`:**
```python
@dataclass
class UseBuiltinOutcome:
    type_id: str
    marker_override: str | None

@dataclass
class CompileSuccessOutcome:
    spec: CustomTypeSpec
    preview: list[PreviewMatch]   # PreviewMatch(segment_text, matched_text, start, end)

@dataclass
class AskOutcome:
    question: str
    options: list[str]
    target: str

@dataclass
class CannotCompileOutcome:
    reason: str

CompileOutcome = UseBuiltinOutcome | CompileSuccessOutcome | AskOutcome | CannotCompileOutcome

class CompilerAgent:
    MAX_ASK_ROUNDS = 3
    
    def __init__(self, llm: LLMProvider, registry: EntityTypeRegistry) -> None
    
    def compile(
        self,
        description: str,
        segments: Sequence[Segment] | None = None,  # 2-3 сегмента для preview
        round: int = 1,
        previous_answer: str | None = None,
    ) -> CompileOutcome
```

Логика:
1. Строит system prompt (из `prompts.py`): паспорт executor'ов + реестр built-in + ограничения
2. Строит user prompt: description + (если `previous_answer`) ответ на прошлый вопрос
3. `llm.complete(messages)` → парсит JSON `{"outcome": "...", ...}`
4. Если `compile` → `validate_regex_pattern` → preview на 2-3 сегментах → `CompileSuccessOutcome`
5. Если `ask` и `round < MAX_ASK_ROUNDS` → `AskOutcome`
6. Если `ask` и `round == MAX_ASK_ROUNDS` → `CannotCompileOutcome(reason="превышен лимит уточнений")`
7. Если `use_builtin` → `UseBuiltinOutcome`
8. Если `cannot_compile` → `CannotCompileOutcome`

**`src/masker/compile/prompts.py`** — шаблон system prompt:
- Таблица executor'ов с правилами выбора
- Таблица built-in типов (id → title)
- Ограничения: русский лейбл + описание обязательны для GLiNER, regex для фиксированных шаблонов, class E не поддерживается
- Выходной JSON-формат с четырьмя исходами

**`tests/masker/compile/test_compiler.py`** — FakeLLM для unit-тестов:
- `test_compile_literals_outcome`
- `test_ask_round_limit_returns_cannot_compile`
- `test_use_builtin_detected`
- `test_partial_success_5_types_one_fails` (batch через несколько вызовов)
