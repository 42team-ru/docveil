# План: OCR для скан-PDF на базе PaddleOCR

## Контекст

Проект `triema-masker` сейчас понимает PDF только с настоящим текстовым слоем
(`backend/src/masker/ingest/pdf_ingest.py` → `pymupdf.get_text("rawdict")`,
символьные боксы, `page_chars()`). Скан-PDF формально в архитектуре зарезервирован
(`ARCHITECTURE.md`: якорь `(page, bbox)` от OCR, ветка `IngestAgent`), но кода нет,
диспетчер в `graph/nodes.py::extract_node` различает форматы только по расширению,
в `pyproject.toml` OCR-зависимостей нет, в `fixtures/labeled/` нет ни одного
скана. Одновременно `docs/WIN-PLAN.md` (P1-2) фиксирует OCR как «фичу со
звёздочкой» ТЗ с зафиксированной приёмкой: на `scan_01.pdf` найдены ИНН и ФИО,
их нет в выходном файле ни в тексте, ни визуально. `docs/SCORING.md` оценивает
задачу в 3–5 дней и относит к волне 2.

**Что решаем.** Ввести полноценную ветку скан-PDF: пер-страничный роутинг
между текстовым и OCR-разбором, чистка двух слоёв (пиксели + невидимый
текстовый слой) при рендере, и всё это за абстракцией OCR-провайдера
(`MASKER_OCR=paddle|tesseract|fake`), по аналогии с `MASKER_LLM`. Основной
движок — PaddleOCR (PP-OCR по умолчанию, PaddleOCR-VL опционально), плюс
`fake`-провайдер для CI без весов и сети.

**Ключевые архитектурные решения**, зафиксированные в диалоге:

1. **Абстракция провайдера** `OCRProvider` в `src/masker/ocr/`: `fake` для юнитов,
   `paddle` (PP-OCR) как основной, `paddle_vl` и `tesseract` — регистрируются,
   но их вес не тянется в CI. Ключ выбирается `MASKER_OCR`, дефолт — `fake` при
   отсутствии переменной (не пытаться скачать веса на импорте).
2. **Пер-страничный роутинг**, а не по документу: страница считается сканом,
   если после `page.get_text("rawdict")` непустого текста нет **или** он OCR-невидим
   (см. эвристику ниже). Смешанные PDF работают из коробки.
3. **Двухслойная чистка**: при рендере скан-страницы мы (а) выжигаем пиксели
   исходной сущности прямоугольником, (б) поверх кладём тот же маркер, что и
   для текстового PDF (лестница `mask.labels.marker_ladder`), (в) добавляем
   **невидимый текстовый слой** с обезличенным текстом всей страницы, чтобы
   copy-paste из результата давал маскированный текст, а не исходный.
4. **Автодескью 0/90/180/270** через `use_doc_orientation_classify=True`
   у PaddleOCR; рукопись — не в штате, но не ломать пайплайн на ней.
5. **Корпус для приёмки — гибрид**: `fixtures/labeled/scan_synth_*.pdf` —
   детерминированно генерятся из существующих `contract_*.docx` через
   `docx → PDF → рендер каждой страницы в изображение → пересборка PDF из
   изображений`, разметка переносится из `.labels.json` через координатный
   маппинг. Реальные сканы кладутся в `fixtures/holdout/scans/` под
   `@pytest.mark.scans_real` и в CI не запускаются.
6. **Инвариант «не тащить веса на импорте»**: `paddleocr` — extra в
   `pyproject.toml` (`ocr = ["paddleocr>=3.0"]`), ленивая инициализация внутри
   провайдера, `make gate` в CI гоняет `MASKER_OCR=fake`.

## Разбиение на подзадачи

Пять подзадач, каждая — самостоятельно проходит `make gate`. Порядок жёсткий:
следующая опирается на контракты предыдущей.

### O1 — Контракты и абстракция OCR-провайдера

**Файлы:** `backend/src/masker/ocr/__init__.py` (новый), `ocr/provider.py`,
`ocr/fake.py`, `ocr/select.py`; `backend/pyproject.toml` (extra `ocr`);
`backend/src/masker/model.py` (расширить `Anchor` семантику `("page", bbox)`
для скан-локатора и добавить `Segment.origin`); `backend/masker.llm.yaml`
(рядом положить `masker.ocr.yaml` — конфиг провайдеров).

**Что делаем.**

- `OCRProvider` Protocol с одним методом
  `recognize(image: numpy.ndarray, dpi: int) -> tuple[OCRLine, ...]`.
  `OCRLine` — dataclass с полями `text: str`, `bbox: tuple[float, float, float, float]`
  (в пиксельных координатах изображения), `confidence: float`,
  `polygon: tuple[tuple[float, float], ...]` (4 угла для повёрнутого текста).
- `FakeOCR` — читает соседний с изображением `*.ocr.json` (заранее заготовленный
  для тестов), возвращает детерминированный список строк. При отсутствии файла —
  возвращает `()`, а не бросает исключение (симулирует пустой скан).
- `select_ocr(name: str | None) -> OCRProvider` в `ocr/select.py`, читает
  `MASKER_OCR`, дефолт `fake`. Импорт `paddle`/`tesseract` — ленивый внутри
  ветки, чтобы CI без extra не падал.
- `Segment.origin: str = "text"` — маркёр происхождения сегмента (`"text"` |
  `"ocr"`), нужен рендеру, чтобы выбрать правильный путь редакции. Дефолт не
  меняет существующие сегменты. Правки минимальные: добавление поля со значением
  по умолчанию, тесты сравнения сегментов уже используют `dataclasses.replace`
  либо явные поля.
- Тест `tests/ocr/test_provider_selection.py`: `MASKER_OCR=paddle` в окружении
  без extra `ocr` — селектор возвращает `paddle`, но при первом вызове
  `.recognize()` даёт `RuntimeError` с понятным сообщением про `pip install
  triema-masker[ocr]`, а не голый `ModuleNotFoundError`. Второй тест: с extra
  `ocr` и `MASKER_OCR=fake` в `pyproject`/CI — импорт `masker.ocr` не тащит
  `paddleocr`.
- Тест `tests/ocr/test_no_ocr_imports_outside_layer.py` — по аналогии с
  `test_no_llm_imports_outside_layer`: `paddleocr` не импортируется нигде вне
  `src/masker/ocr/`.

**Приёмка O1.**

- `make gate` = 0 с `MASKER_OCR=fake` (значение по умолчанию).
- Тесты выше зелёные.
- `pip install -e .[ocr]` устанавливает `paddleocr`, `pip install -e .` — нет.

### O2 — PaddleOCR-адаптер (PP-OCR)

**Файлы:** `backend/src/masker/ocr/paddle.py` (новый), `backend/pyproject.toml`
(добавить `paddleocr>=3.0` в extra `ocr`), `backend/masker.ocr.yaml`.

**Что делаем.**

- `PaddleOCR`-провайдер: одна ленивая инициализация на процесс
  (`PaddleOCR(lang="ru", use_doc_orientation_classify=True,
  use_textline_orientation=True, use_doc_unwarping=False)` — точный набор
  параметров по актуальному API v3.x, подтверждён через Context7).
  Кириллица: если `lang="ru"` не сработает — фолбэк `lang="cyrillic"` со
  специальным тестом-детектором версии.
- `.recognize()`: принимает `numpy.ndarray` (BGR), возвращает `tuple[OCRLine, …]`.
  Из `predict()`-результата достаём для каждой строки: `rec_texts[i]`,
  `rec_scores[i]`, `rec_polys[i]` → полигон 4×2 → axis-aligned bbox (min/max).
- Веса кэшируются в `~/.paddleocr/` (стандарт Paddle), не в репе.
- Детерминизм: `PaddleOCR` внутри детерминирован на CPU (сеть). Один тест
  `@pytest.mark.models`, гоняет один синтетический PNG дважды и сравнивает
  результат побайтово.
- Опционально готовим слот `paddle_vl` (класс-обёртка над PaddleOCR-VL через
  тот же интерфейс) — только скелет, чтобы структура кода не переворачивалась,
  когда до VL дойдут руки. Реальную VL-ветку в этой итерации **не реализуем**
  (SGLang, 1.7B — отдельная история).

**Приёмка O2.**

- Тест `test_paddle_recognize_smoke` (маркер `models`, из CI исключён): на
  подготовленном PNG с русским текстом «Иванов ИНН 7707083893» — PaddleOCR
  находит ИНН как строку с confidence ≥ 0.9 и валидной bbox.
- `MASKER_OCR=paddle make demo` работает на одном подготовленном скан-PDF без
  падений и без сети (веса могут докачаться на первый прогон — это ок).

### O3 — Скан-ingest: страница → сегменты

**Файлы:** `backend/src/masker/ingest/pdf_ingest.py` (расширяем),
`backend/src/masker/ingest/scan_ingest.py` (новый — вспомогательный, чтобы
`pdf_ingest.py` не разросся), `backend/src/masker/graph/nodes.py::extract_node`
(инъекция `ocr` через `RunDeps`), `backend/src/masker/pipeline.py::RunDeps`
(добавить `ocr: OCRProvider`).

**Что делаем.**

- В `ingest_pdf` пер-страничный роутер `_page_is_scan(page) -> bool`:
  1. Если `page.get_text("text")` пустой — скан.
  2. Если непустой, но покрывает <5% площади страницы и одновременно есть
     изображения (`page.get_images()`) → скан-с-невидимым-OCR (двухслойная
     ловушка): рассматриваем как скан, потому что текст под картинкой не
     соответствует тому, что видит человек, и его всё равно надо стереть.
     Эвристика реализуется как `char_coverage_ratio()`, пороги пишем как
     константы с обоснованием в докстринге. Численные пороги калибруются на
     синтетическом корпусе O5 и на реальном holdout.
  3. Иначе — обычная текстовая страница, как сейчас.
- Для скан-страницы: рендер в PNG 300 dpi (`page.get_pixmap(dpi=300)` в BGR),
  вызов `ocr.recognize(img, dpi=300)`, каждая `OCRLine` становится одним
  `Segment`. Якорь: `Anchor(fmt="pdf", locator=("page", page_num, "ocr",
  int(x0*100), int(y0*100), int(x1*100), int(y1*100)), label=f"стр. {page_num+1} (скан)")`
  — координаты в pt страницы, не пикселях; масштаб `pt_per_px = 72/dpi`
  применяем при укладке. Целочисленное представление в локаторе сохраняет
  контракт `Anchor.locator: tuple[str|int|float, ...]` и гарантирует хешируемость.
  Второй элемент `"ocr"` — метка типа локатора, чтобы рендер различал текст vs
  скан без чтения `Segment.origin`.
- `Segment.origin = "ocr"`, `Segment.text = OCRLine.text`. Внутри-сегментные
  смещения `Entity.start/end` работают как есть — детектор регулярок и Natasha
  видят обычные строки, никакой ветки в детекции.
- Инвариант: смешанный PDF даёт список сегментов, где часть — `origin="text"`
  с символьным якорем, часть — `origin="ocr"` с bbox-якорем. Порядок
  сохраняется страничный + внутри страницы top-to-bottom, left-to-right (тот
  же, что даёт PaddleOCR).
- `extract_node` получает `ocr = deps.ocr` (см. правки `RunDeps`), передаёт в
  `ingest_pdf(path, ocr=ocr)`. Для DOCX ветки — `ocr` не запрашивается,
  ленивая инициализация не срабатывает.

**Приёмка O3.**

- Тест `tests/ingest/test_pdf_scan_router.py`: подложенный PDF с одной пустой
  страницей и одной текстовой — маршрутизация по каждой странице отдельно,
  скан идёт в `FakeOCR`, текст — в существующий путь.
- Тест «двухслойная ловушка»: PDF, у которого под изображением лежит
  невидимый `[?][?][?] ИНН 7707083893` (сгенерирован в `spikes/` для теста) —
  роутер помечает страницу как скан, `Segment.origin="ocr"`, сегменты берутся
  из `FakeOCR`, а не из невидимого текста.
- Существующие тесты `ingest_pdf` не падают (проверка регресса на текстовых
  PDF из `fixtures/labeled/contract_pdf_*.pdf`).

### O4 — Рендер: чистка обоих слоёв + невидимый OCR-слой

**Файлы:** `backend/src/masker/render/pdf_render.py` (ветка для
`origin="ocr"`-сегментов), `backend/src/masker/mask/labels.py` (не трогаем —
переиспользуем `marker_ladder`).

**Что делаем.**

- В `pdf_render.py` вводим `_replacement_regions_ocr(repl, page)`,
  возвращающий тот же `dict[str, tuple[PdfRegion, ...]]` (erase/paint/label),
  но геометрия строится не из символьных боксов, а из bbox сегмента-строки,
  пропорционально смещению `entity.start/end` внутри `segment.text` (линейно,
  как если бы шрифт был моноширинным — для OCR-строк этого достаточно, потому
  что вписывать маркер мы будем поверх стёртой полосы, а не пытаться попасть в
  каждый глиф).
- **Пиксельный слой (первый).** `add_redact_annot(rect, fill=(1,1,1))` +
  `apply_redactions(images=PDF_REDACT_IMAGE_PIXELS_INSIDE)` для скан-страниц —
  это осмысленное изменение от текущего `PDF_REDACT_IMAGE_NONE`, критично для
  сканов. Для страниц с `origin="text"` поведение не меняется (флаг
  выставляется пер-страничным вызовом `apply_redactions`, не глобально).
- **Маркер поверх.** Тот же `marker_ladder`, что и для текстовых страниц, с
  полом 8 pt. Позиция подписи — центр `erase_regions[0]`, чтобы не наезжать
  на соседние строки OCR. Строка тянется из `PdfRegion.y0/y1`.
- **Невидимый текстовый слой (второй).** После пиксельной чистки на скан-странице
  вставляем `page.insert_text(pos, masked_line, render_mode=3, fontsize=1)`
  (`render_mode=3` — невидимый глиф) для каждой OCR-строки, но с уже
  обезличенным текстом (в тексте сегмента исходные значения заменены на
  маркеры). Так copy-paste из результата даёт маскированный текст, а не
  исходный. Тест на утечку через copy-paste — часть приёмки.
- Идемпотентность: повторный прогон обезличенного файла (у которого сканы уже
  чистые, а текстовый слой — уже маскированные строки) на новых сегментах не
  находит критичных сущностей, второй прогон побайтово равен первому.

**Приёмка O4.**

- Тест `test_scan_render_wipes_pixels`: на `scan_synth_01.pdf` рендерим,
  вырезаем регион сущности из результата → OCR (тот же `FakeOCR` с новой
  разметкой) не находит исходной строки в этом регионе.
- Тест `test_scan_render_wipes_text_layer`: `pymupdf.get_text("text")` от
  результирующей страницы не содержит ни одной исходной строки критичных
  сущностей.
- Тест `test_scan_render_idempotent`: два прогона побайтово равны.
- Инвариант «структура цела» — `Certificate` (`model.py::Certificate`) на
  скан-PDF собирается и не падает.

### O5 — Корпус, метрики, ворота

**Файлы:** `backend/scripts/gen_scan_fixtures.py` (новый — генератор
синтетических сканов), `backend/fixtures/labeled/scan_synth_01.pdf` и `.labels.json`
(результат генератора, коммитятся), `backend/fixtures/holdout/scans/` (пусто в
репе, только `.gitkeep`), `backend/src/masker/eval.py` (порог по OCR-корпусу),
`AGENTS.md` / `docs/TASKS.md` (добавить задачу, обновить статус).

**Что делаем.**

- Генератор: берёт `contract_pdf_01.pdf`, каждую страницу рендерит в PNG
  300 dpi через PyMuPDF, собирает новый PDF из этих PNG (без текстового слоя).
  Разметка `.labels.json` копируется с добавлением поля `bbox` (пересчитанного
  через `page.search_for(entity_text)` на исходной странице → координаты).
  Детерминистично: тот же исходник даёт побайтово тот же скан.
- Сколько фикстур: `scan_synth_01` (простой), `scan_synth_02_rotated` (страницы
  повёрнуты на 90°), `scan_synth_03_mixed` (страницы 1–2 текстовые, страница 3 —
  скан) — три файла хватает, чтобы прокрыть ключевые ветки роутера.
- В `make eval`: подмножество `--set=scans` считает precision/recall на
  скан-корпусе с `MASKER_OCR=fake` в CI (в fake кладём OCR-строки, идеально
  совпадающие с текстом исходника — тогда метрика мерит рендер, а не качество
  движка) и с `MASKER_OCR=paddle` локально (маркер `models`).
- Ворота в `eval.py::_print_profile_judge` (и рядом): добавить порог
  `scan_critical_recall == 1.0` на `scan_synth_*`. Точный порог `person recall`
  и `org recall` — калибруются после первого прогона Paddle; в план кладём
  «≥0.90 на прямых сканах», реальные цифры пишутся в отчёт задачи и в
  `docs/handoff/`.
- Обновить `AGENTS.md` (раздел про формат) и `TASKS.md` (ввести новую задачу
  `Р-OCR` или `T2.3-new` — на выбор пользователя, в плане предлагаю `Р-OCR`
  для консистентности с текущей нумерацией «Р» = распознавание).

**Приёмка O5.**

- `make gate` = 0 с `MASKER_OCR=fake`, включая новый порог по сканам.
- `MASKER_OCR=paddle make eval --set=scans` локально даёт recall 1.0 по
  критичным типам на `scan_synth_*`.
- Реальный holdout: 2–3 скана вручную прогнаны и вклеены в отчёт задачи —
  цифры не блокируют ворота, но фиксируются как факт.

## Что переиспользуем без изменений

- `mask/labels.py::marker_ladder` — лестница отступления работает на OCR-строках
  без правок; она принимает только `label` и `available_width`, а не текстовые
  боксы.
- `mask/keys.py::group_key` — согласованность псевдонимов автоматически работает
  для сущностей из OCR, потому что ключ строится по `Entity.normalized`, а не
  по типу сегмента.
- `render/pdf_render.py::_quantize_erase_rect`, `_free_extension_*` —
  квантование ширины и границы расширения одинаковы для текста и OCR (защита
  от bit-leak через ширину прямоугольника, доказанный канал утечки).
- `detect/*` — детекция ест `document.text()` без изменений, для неё
  происхождение сегмента прозрачно. Регрессия по recall на текстовых PDF
  проверяется существующими фикстурами.
- `validate/*` — `ValidateAgent` прогоняет детекторы по артефакту; для скана
  ему тоже нужен OCR-прогон результата, чтобы искать утечки визуально; это
  делается тем же `deps.ocr`.
- `graph/nodes.py::extract_node` — контракт JSON-стейта не меняем, добавляем
  только `origin` в сериализацию сегмента (обратно совместимо: старые
  чекпойнты без поля читаются как `origin="text"`).

## Проверка end-to-end

1. `make gate` из `backend/` — базовые тесты, `MASKER_OCR=fake` по умолчанию.
2. `MASKER_OCR=paddle python -m masker.cli mask fixtures/labeled/scan_synth_01.pdf
   --types inn,person --out out/scan_synth_01/` — реальный прогон Paddle.
3. Открыть `out/scan_synth_01/scan_synth_01.masked_highlight.pdf`:
   - визуально: маркеры `[Ф1]`, `[ИНН]` стоят поверх обезличенных полей;
   - `pdftotext out/.../scan_synth_01.masked_highlight.pdf -` — нет ни одной
     исходной строки критичных сущностей;
   - copy-paste из PDF-читалки: тоже нет исходных строк.
4. `python -m masker.cli mask out/.../scan_synth_01.masked_highlight.pdf …`
   повторно — вывод побайтово равен первому прогону (идемпотентность).
5. `make eval --set=scans` — precision/recall в `eval_report.json`, recall
   критичных = 1.0.
6. Реальный скан из `fixtures/holdout/scans/` (не в CI): убедиться глазами,
   что PP-OCR попал в основные ФИО/ИНН, отчёт вклеить в handoff.

## Порядок выполнения и оценки

- O1 (контракты) — 0.5 дня. Отдельная ветка `feat/ocr-provider-abstraction`.
- O2 (Paddle-адаптер) — 1 день. Ветка `feat/ocr-paddle`.
- O3 (ingest роутер) — 1 день. Ветка `feat/ocr-scan-ingest`.
- O4 (рендер + невидимый слой) — 1–1.5 дня. Ветка `feat/ocr-scan-render`.
- O5 (корпус, ворота, документация) — 0.5–1 день. Ветка `feat/ocr-fixtures-and-gate`.

Итого 4–5 дней, сходится с оценкой `docs/SCORING.md` (3–5).

## Явные не-цели (что вне скоупа этой итерации)

- Полноценный **PaddleOCR-VL 1.7B** на SGLang: слот в `ocr/paddle_vl.py`
  оставляем, реальную реализацию — отдельной задачей после защиты.
- **Рукопись**: не в приёмке, но пайплайн не должен падать на рукописных полях.
- **Не-русский OCR** кроме `rus+eng`.
- **Правки веб-морды**: скан-режим включается тем же CLI/HTTP-контрактом, что
  и текстовый PDF, отдельного тумблера в UI не добавляем.
