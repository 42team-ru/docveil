# Разрывы CLI и API

Сверка выполнена по `backend/src/masker/cli.py`, `docs/CLI.md`, роутерам
`runs.py` и `custom_types.py` и их схемам на 2026-09-10.

## Реальные разрывы

- CLI поддерживает `--llm-config <yaml>`, а `POST /runs` не принимает ни путь,
  ни идентификатор конфигурации LLM. API выбирает провайдер только из
  конфигурации процесса через dependency `get_llm_provider`.
- CLI требует явный `--allow-remote-pii` перед отправкой исходных PII в
  удалённый OpenRouter. В API нет аналогичного флага согласия на конкретный
  прогон.
- CLI создаёт `report.html` по `--html` (для DOCX). API отдаёт JSON-отчёт и
  рендер-артефакты, но не умеет запросить или скачать HTML-отчёт.
- CLI может включить `--llm-trace` и получить содержащие PII
  `llm-trace.jsonl`/`llm-trace.md`. У API нет ни флага включения трейса, ни
  эндпойнта для его выдачи.
- CLI допускает пакетный запуск нескольких файлов одной командой; REST
  принимает один `object_name` за `POST /runs`. Несколько файлов по API
  возможны только несколькими запросами клиента.
- CLI предоставляет операционные параметры `--thread-id`, `--state-db` и
  `--fresh`; API всегда создаёт случайный `thread_id`, а выбор/сброс
  чекпойнтера остаётся конфигурацией сервера. Это разрыв управления запуском,
  а не обработки документа.
- CLI без `--ask` выполняет прогон без паузы и применяет default-решения. API
  всегда передаёт в граф `interactive=True`, а `RunCreateRequest` не содержит
  способа это отключить. Клиент обязан обработать `awaiting_answers`; E2E
  папка коллекции делает это автоматически.

## Проверка известных предположений

- Выбора цвета фона подсветки в API действительно нет. Но его нет и в CLI:
  цвет зашит в рендерере. Поэтому это дефицит продукта, но не разрыв CLI/API.
- Режима OCR в API нет. В текущем CLI такого режима также нет: CLI принимает
  только DOCX/PDF, а сканированный PDF/OCR отмечен в планах как ещё не
  реализованная работа. Это тоже не разрыв CLI/API.

## Смежный дефект API

`POST /files/upload` технически принимает XLSX, но `POST /runs` отклоняет
такой `object_name` с 422: `api.services.run_service.SUPPORTED_SUFFIXES`
содержит только `.docx` и `.pdf`. CLI также пока не принимает XLSX, поэтому
это не разрыв именно между интерфейсами, но это несоответствие заявленному
формату продукта и причина, по которой коллекция предлагает для запуска
только PDF/DOCX.
