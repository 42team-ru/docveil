# Postman: Triema Masker API

Импортируйте оба файла из этой папки: коллекцию
`triema-masker.postman_collection.json` и окружение
`triema-masker.postman_environment.json`. После импорта выберите окружение
**Triema Masker - Local**.

В окружении заполните `base_url`, `user_email`, `user_password` и
`input_file`. Последний — абсолютный путь к существующему PDF или DOCX на
машине, где запущен Postman. Пароли намеренно оставлены плейсхолдерами и не
хранятся в репозитории. Для административных запросов также заполните
`admin_email` и `admin_password`.

## Сквозная проверка

Запустите в Collection Runner только папку **E2E - Mask document**. Она сама
передаёт `object_name` из ответа upload и `run_id` из ответа create run; ID
копировать не нужно. Установите в Runner `Request delay` в 1000 ms.
`poll_max_attempts` по умолчанию равен 60, то есть тайм-аут ожидания составляет
примерно минуту.

Путь выполняется в следующем порядке:

1. логин пользователя;
2. загрузка файла;
3. `POST /runs` с `mask_style=both`, `profile=false`, `review=false`;
4. повторный `GET /runs/{id}` до `done`; если API остановится на вопросах
   политики, коллекция автоматически получит их и отправит все default-ответы;
5. получение отчёта, списка артефактов и `masked_highlight`.

`profile=false` и `review=false` здесь намеренны: они отключают LLM-профили и
проверку оператора. Вопросы политики API всё равно может сформировать для
найденных PII, поэтому E2E автоматически принимает их default-ответы.
Отдельные папки проверяют обе интерактивные паузы вручную. Сквозной тест требует, чтобы отчёт прошёл
валидацию (`certificate.ok=true`) и не содержал утечек (`leaked=[]`).

## Остальные папки

- **Run history and negative cases** покрывает список с фильтрами, отсутствующий
  UUID, чужой UUID (ожидается 404, чтобы не раскрывать владение) и запрос без
  токена. Для второго случая задайте `foreign_run_id` как UUID настоящего
  прогона другого пользователя.
- **Run questions and answers** требует `question_run_id` в состоянии
  `awaiting_answers`. Сначала отправьте GET: он выберет первый вопрос и его
  вариант по умолчанию для следующего POST.
- **Operator review edits** требует `review_run_id` в состоянии
  `awaiting_review` и хотя бы одну найденную сущность. GET сохранит её `ref`,
  а POST отправит операторское решение `keep`.
- **Custom data types** требует уже заполненного `uploaded_object_name`.
  `Compile custom type` может вернуть `done` либо `waiting`. Второй запрос
  папки запускайте только для `waiting`; при `done` сервер корректно ответит
  404, потому что отвечать уже не на что.

Сервер для проверки этой коллекции должен иметь PostgreSQL/SQLite-чекпойнтер,
MinIO и настроенный LLM-провайдер. В репозитории коллекция выверена по
роутерам и Pydantic-схемам, но не исполнялась: локальная среда не содержит
этих зависимостей.
